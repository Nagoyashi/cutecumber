# v0.7.0 — Page builder (staging)

The dashboard's links-list editor grows into a **page builder**: a creator's
public page becomes a vertical stack of pre-composed, full-width sections they
pick and fill, plus the surface for a paid **sprout** tier. The whole thing
ships **behind a flag** (`BUILDER_ENABLED` + an allowlist) — production keeps the
current links editor untouched until the switch is flipped, so this release adds
the capability without changing what anyone sees yet. All migrations are
additive; the public page stays server-rendered.

## Data model

- **Section model** (`app/sections.py`), same doctrine as the theme engine:
  strict validation on save, tolerant resolution on render, a versioned shape.
  Ten section types — hero, links, gallery, about, socials, divider, embed,
  mail-list, form, custom-html — each with a few hand-tuned style variants. (#75)
- **Additive migration**: `sections_draft_json` / `sections_live_json` (a
  draft/live split — edit privately, publish when ready) and a `plan` column.
  Existing rows are untouched and keep rendering the legacy links page. (#74)
- **Theme**: a computed `line` token, and the two premium presets (lavender
  haze, midnight snack) are now sprout-only. (#76)

## The builder

- **Editor** (`/dash/builder`, staging): an in-canvas editor — sections render
  on the page and are selectable with a hover tool cluster, drag-to-reorder, a
  section drawer, autosave, publish, phone preview, a page-theme picker, and
  four starter templates. (#77)
- **Public rendering**: the section stack is server-rendered from the published
  copy; the legacy links page still renders when a user has no live sections.
  (#78, #79)
- **Gallery photo uploads** reuse the avatar pipeline (re-encoded WebP, EXIF/GPS
  stripped by re-encode); orphaned files are swept by `flask gc-images`. (#81)
- **Premium tier**: the embed / mail-list / form / custom-html sections and the
  two premium themes gate on `plan`; a staging-only toggle exercises them without
  billing (real billing is a later cycle).

## Public-page exceptions (scoped, documented)

The public page's zero-JS / zero-third-party / strict-CSP budget still holds
everywhere except the two section types that need more, each armed per-page and
nowhere else (`RULES.md`, `DECISIONS.md` #38):

- **Embeds** are click-to-load — one self-hosted script plus the
  youtube-nocookie / spotify frame hosts — so no third-party request happens
  until the visitor clicks.
- **Custom HTML** renders in a sandboxed, network-blocked iframe: no scripts run
  and nothing phones home.
- **Mail-list / form** sections link out to the creator's own destination — no
  on-site collection, no visitor data stored.

## Notes

Nothing is exposed to visitors yet: everything is behind `BUILDER_ENABLED`, off
in production. This release lands the code; enabling it in prod (gated on a
real-browser QA pass, #34) and billing come in a later cycle.
