# v0.9.0 — Page builder for everyone; sprout "coming soon"

`v0.8.0` turned the page builder on for an allowlist; **`v0.9.0` opens it to
every creator** and makes it the primary way to edit a page. The paid **sprout**
tier is surfaced as **"coming soon"** with a work-in-progress payment placeholder
— real billing is still a later cycle.

## Open to all creators

- The builder is now the **primary editor**: the dashboard leads with an "open
  the builder" call-to-action; the classic links editor stays as the secondary
  path. A public page still switches to the section stack only once its owner
  publishes. (#91)
- The access gate is simplified — the `BUILDER_ENABLED` flag alone grants access
  (flag-off is still a plain 404). The former access allowlist is repurposed to
  an internal-test set. (#90)

## Sprout is "coming soon"

- The premium sections (embeds, mail-list, form, custom HTML) and the two premium
  themes show a **coming-soon** badge — not a buy/upgrade — and the upsell is a
  "sprout is coming soon, payments are a work in progress" placeholder with no
  price and no checkout. (#92)
- No self-upgrade: the staging plan toggle is restricted to the internal-test
  set, so the premium tier can still be exercised internally before billing
  exists. (#92, #93)

## Safe by construction

Opening access exposes only the **six free, server-rendered section types** —
hero, links, gallery, about, socials, divider — built from validated tokens, with
zero JS and no third-party requests. The risky section types stay
premium/coming-soon, so the public-page CSP exceptions (the sandboxed custom-HTML
iframe and click-to-load embeds) stay **dormant** — no new public attack surface
until sprout + billing ship. (`DECISIONS.md` #38, #94)

## Under the hood

- The now-public builder write endpoints (save / publish / upload / preset) are
  rate-limited. (#93)

## Notes

Real billing (Stripe) is still deferred — sprout opens for real when it lands.
